# ADR-0023: ホーム図は画面の幅で横と縦を切り替え、番線のカードに収める（回してよいが、鏡写しにしない）

## コンテキストと課題

ADR-0017 の見本（`assets/0017/source/Station.dc.html`・`Platform.dc.html`）は、駅ページの番線のカードに「ホーム図を見る」のボタンを置き、
番線ごとの別ページに**縦の図**（「上が 1号車」の添え書きつき）を出す形だった。
見本は見た目で決めたもので、利用場面から確かめたものではない（[`assets/0017/README.md`](./assets/0017/README.md)「見本にあることは、実装する約束ではない」）。

利用者は駅で、目の前のホームと図を見比べてエレベーターや乗る位置を探す。図が現実と違う向き、特に**鏡写し**になると、左右を取り違える。
号車番号は列車の側の事情で、ホームの形はひとつである（埼京線と湘南新宿ラインのように、同じホームに号車の並びが逆の列車が来る）。
このため、号車番号を基準に図の向きを決めることはできない。

一方で、横の図はスマホの幅では横スクロールが長くなり、縦の図は PC の幅では余白が多い。

## 決定

1. **図は回してよいが、鏡写しにしない。** 基準は「線路に向かって立った見え方」（列車が奥、ホームが手前、左右は実際どおり）。
   1号車を上・左に揃えない。ADR-0022 の原点の約束により、どのホームも回すだけでこの見え方になる
2. **画面の幅で向きを切り替える。** `lg`（1024px）以上は横の図（列車が上、ホーム・設備・プレートが下）。
   `lg` 未満は縦の図（横の図を左へ90°回したもの。列車が左、設備・プレートが右）。「上が 1号車」の添え書きは使わない
3. **別ページを作らず、駅ページの番線のカードに収める。** `lg` 未満では番線のカードを折りたたみ（既定で閉じる）、`lg` 以上ではいつも開いておく

## 却下した選択肢

### 見本どおり、すべての端末で縦の図を番線ごとの別ページに出す

- 縦の図だけでは、PC の幅で図が細長くなり、横の余白が無駄になる
- 別ページにすると、番線を見比べるたびにページを行き来する。駅ページで方面タブと番線を見渡せる今の形が失われる
- 別ページの目的（スマホで1つの番線に集中する）は、折りたたみで他の番線を閉じておけば果たせる

### 1号車を上（縦の図）や左（横の図）に揃える

- 同じホームに号車の並びが逆の列車が来ると、列車ごとに図が鏡写しになり、同じホームの設備の位置が列車によって左右入れ替わる
- 揃えた向きがそのホームの現実と逆なら、図全体が現実の鏡写しになる

### 縦の図に「上が 1号車」の添え書きを付ける

決定1 により、縦の図の上は1号車とは限らない。向きは「線路に向かって立った見え方を回したもの」で一定なので、添え書きで補う必要が無い。

### すべての端末で横の図にする（今の形）

スマホでは、図の幅（ホーム長 × 1メートルあたりの画素数）が画面より大きく、横スクロールで設備とプレートを追うことになる。
縦の図なら、指で縦に送るだけで端から端までたどれる。

## 影響

- ホーム図の部品に縦の図が加わる。横の図と縦の図は同じデータ（ホーム座標）を使い、回し方だけが違う
- 横と縦の切り替えは CSS（`lg:`）で行い、最初の描画から正しい向きで出す。番線のカードの開け閉めも同じ
- Admin は横の図のまま（編集は PC で行う）。見た目は Web の横の図と揃える
- 縦の図のプレートの置き方は、ADR-0006（文字は HTML のオーバーレイに置く、実測しない）の範囲で決める

## 再評価の条件

- 縦の図のプレートを、実測せずに読める形で置けないと分かったとき（ADR-0006 と合わせて見直す）
- 利用者から、番線ごとに共有できる URL（別ページ）を求められたとき
