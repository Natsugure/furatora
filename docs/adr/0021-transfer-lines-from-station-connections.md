# ADR-0021: 乗り換えられる路線を乗換接続（stationConnections）から導き、乗換単位（stationGroups）を乗換の判定に使わない

- **ステータス**: Accepted
- **日付**: 2026-10-20
- **決定者**: @Natsugure
- **関連**: [`docs/domain/station-master-model.md`](../domain/station-master-model.md)「コード体系」「乗換接続」,
  [ADR-0007](./0007-station-master-data-source.md), GitHub Issue #172 / #96 / #166

---

## コンテキストと課題

「この駅で乗れる・乗り換えられる路線」は、駅の詳細の見出しに限らず、検索結果・駅の一覧などで使う見込みがある（#172）。
乗換先を導く出どころの候補は2つある。

- **乗換接続**（`stationConnections`）: 駅と駅の有向の組。初回シードで同じ `station_g_cd` の全順序対から機械生成し（`ekidata_group`）、
  以後は Admin で追加・削除する（`manual`）
- **乗換単位**（`stationGroups`）: ekidata `station_g_cd`。1駅は高々1グループに属する

2026-10-20 時点の本番データでは、御茶ノ水のグループ（`station_g_cd = 1131203`）に、淡路町（丸ノ内線）・小川町（都営新宿線）・
新御茶ノ水（千代田線）・JR御茶ノ水（2路線）・メトロ御茶ノ水（丸ノ内線）がすべて属している。
一方、実際の乗換関係は次のとおりで、**推移的でない**。

- 淡路町・新御茶ノ水・小川町は相互に乗換駅
- 新御茶ノ水–JR御茶ノ水、JR御茶ノ水–メトロ御茶ノ水は乗換駅
- 淡路町–JR御茶ノ水は乗換駅ではない（淡路町–新御茶ノ水、新御茶ノ水–JR御茶ノ水は乗換駅であるにもかかわらず）

初回シードでグループから機械生成した乗換接続には、淡路町–JR/メトロ御茶ノ水のような誤りがあり、開発者が Admin で削除した。

## 決定

1. **乗り換えられる路線は、乗換接続（`stationConnections`）の相手駅の路線から導く。**
2. **乗換単位（`stationGroups`）は、乗換の判定に使わない。** 乗換単位は「どの駅か」を表す単位
   （路線を特定しない検索・ハブページ・同じ名前の別の駅の区別）として扱う。

## 却下した選択肢

### 乗換単位に属する全駅の路線を返す（#172 の案B）

ekidata の定義にそのまま従え、乗換接続の行を管理しなくて済む。次の理由で却下した。

- **1駅が1グループにしか属せない構造では、推移的でない乗換関係を表せない。**
  淡路町–新御茶ノ水と新御茶ノ水–JR御茶ノ水を同じグループで表すと、淡路町–JR御茶ノ水も乗換駅になる。
  グループを分け直しても、重なりのある集合は表せない。
- Admin で手直しした乗換接続（淡路町–JR/メトロ御茶ノ水の削除）が無効になり、誤りが表示に戻る。
- `ekidataStationGroupCd` の nullable 化（#96）でグループを手作業で作れるようにしても、構造の制約は変わらない。

### 乗換接続のつながりを全部たどった連結成分を「乗換駅の集合」とする

乗換接続だけで「駅のまとまり」も作れる。しかし、淡路町からたどると JR御茶ノ水・メトロ御茶ノ水まで同じまとまりに入り、
案Bと同じ誤りになる。手作業の接続が増えるほど、まとまりは際限なく広がる（新御茶ノ水 → 大手町 → 東京 …）。

## 影響

- 乗り換えられる路線は、自駅の路線（`stationLines`）と、乗換接続の相手駅の路線から作る。
  別の駅名の相手駅の路線は、自駅の路線と区別して扱う（相手駅の名前を添える）。
- 乗換の正しさは乗換接続のデータの正しさに依存する。初回シード由来（`ekidata_group`）の行には、グループ由来の誤りが残りうる。
  見つけたら Admin で削除する。
- 乗換単位は乗換と切り離され、「どの駅か」を表す単位として残る。手作業で追加した駅がハブ・名寄せに入れるかは #96 に依存する。

## レビュー

次のいずれかで再評価する。

- 物理駅粒度への統合（#82）で、`stations` の粒度が変わったとき（自駅の路線と乗換先の境界が変わる）。
- 乗換接続の誤りを Admin で直す負担が大きいと分かったとき（グループ由来の行を一括で検証する手段を検討する）。
