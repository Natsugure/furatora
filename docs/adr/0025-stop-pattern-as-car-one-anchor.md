# ADR-0025: 停車位置パターンを号車ごとの区間ではなく「1号車の外側の端＋号車番号の向き」で持つ

## コンテキストと課題

停車位置パターン（ホーム × 列車）は、号車ごとの区間 `[startMeters, endMeters]` を `train_stop_pattern_cars` に持っていた。
号車の数と長さは列車の号車構成（`train_car_structures`）にもあるので、同じ事実を2か所に持つことになる。

- 列車の両数を減らしても、パターンの号車は残る（#215）。図に列車に無い号車が描かれる
- 区間を号車ごとに持つと、同じ列車の同じ号車が駅ごとに違う長さを取れてしまう。現実には起こらない。
  Admin には号車の境界を動かして長さを変える操作があった
- 隣接号車が境界を共有するという不変条件を、図の編集（`moveCarBoundary`）と API の検証の両方で守る必要があった

2026-11-06 時点の本番は 42 パターン・266 号車行で、どの号車も長さが `COALESCE(carLength, 20.0)` と一致し、
号車構成と号車の数が食い違うパターンも無かった。境界を動かして長さを変えたデータは無い。

## 決定

**パターンは「1号車の外側の端の座標」と「号車番号が x のどちらへ増えるか（`plusX` / `minusX`）」だけを持つ。**
号車の区間は、読むたびに号車構成から算出する。

- 基準点を1号車にするのは、号車番号が必ず 1 から始まるため。両数が変わっても1号車の位置は変わらず、最後尾の側が伸び縮みする
- 号車の長さはパターンでは変えない。列車の号車構成（`carLength`）で変える
- 隣接号車が境界を共有することは、算出の仕方から構造的に成り立つ。検証は要らない

## 却下した選択肢

### 号車ごとの区間を残し、合わないパターンがあれば列車の更新を拒む（400）

区間と号車構成の二重持ちが残る。両数を変えたい管理者は、先に全駅のパターンを消すか直す必要がある。
長さの食い違いも防げない。

### 号車ごとの区間を残し、列車の更新と同じトランザクションでパターンの号車を作り直す

消えた号車を消し、増えた号車をどこに足すかを決める処理が要る。その処理は結局「1号車の位置と向きから積む」計算であり、
保存する形を変えるのと同じことを、更新のたびに行うことになる。二重持ちも残る。

### 基準点を「x = 0 に近い側の端」にする

従来の新規作成の入力欄と同じ形だが、最終号車が x = 0 側にある編成で両数が変わると、1号車の位置がずれる。
1号車を基準にすれば、どの編成でも1号車は動かない。入力欄は従来の形のまま、保存の前に換算すればよい。

## 影響

- `train_stop_patterns` に2列が増え、`train_stop_pattern_cars` は廃止する（CLAUDE.md の二段階の手順で DROP する）
- Admin の駅レイアウト編集から、号車の内側の境界を動かす操作がなくなる。編成全体の平行移動は残る
- 区間の算出は Web と Admin の両方が使うので `packages/platform-diagram` に置く（ADR-0015）
- 号車ごとに長さの違う編成は、従来どおり `carLength` で表す

## 再評価の条件

- 同じ列車の号車の長さが、駅によって変わったように扱う必要が出たとき（例: ホームの曲線で停車位置の目安がずれるのを、号車の区間で表したくなったとき）
- 号車番号が 1 から始まらない編成を扱う必要が出たとき
