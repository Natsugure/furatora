# ADR-0022: ホーム座標の原点を「線路に向かって立ったときの左の端」に定め、ホームの側（platformSide）を廃止する

- **ステータス**: Accepted
- **日付**: 2026-10-21
- **決定者**: @Natsugure
- **関連**: [`docs/domain/platform-coordinate-system.md`](../domain/platform-coordinate-system.md),
  [ADR-0006](./0006-diagram-text-in-html-overlay.md), [ADR-0010](./0010-platform-diagram-package-edit-layer.md),
  GitHub Issue #188, #174

---

## コンテキストと課題

ホーム上の位置は、ホームの物理的な一端を `x = 0` とする1次元の座標で持っている。
**どちらの端を `x = 0` にするかは規約で固定しておらず**、ホームごとに管理者が選んできた。
図の向きは、`x = 0` の端と `platforms.platformSide`（図の上で、ホームが列車の上下どちらにあるか）の組で決まっていた。

#174 で、ホーム図を「**線路に向かって立った見え方**」（列車が奥、ホームが手前、左右は実際どおり）を基準に描くことにした。
号車番号は列車の側の事情で、ホームの形はひとつである（埼京線と湘南新宿ラインのように、同じホームに号車が逆の列車が来る）。
したがって図は**回してよいが、鏡写しにしてはならない**。

この見え方で描くには、ホームごとに「線路に向かって左の端はどちらか」が分かっている必要がある。
2026-10-21 時点の本番データは次のとおりだった。

| `platformSide` | ホーム | うち座標を持つ | 向き |
|---|---|---|---|
| 未設定 | 24 | 20 | 「線路に向かって左の端 = `x = 0`」で入力済み（開発者に確認） |
| `bottom` | 8 | 2 | 同上 |
| `top` | 8 | 2（池袋2番線・茗荷谷1番線） | 180°回した向き |

## 決定

**原点を「線路に向かって立ったときの左の端」と定める。** `x` はそこから右の端へ向かって増える。

- `platformSide = top` のホームは、座標を `x' = physicalLength − x` に置き換える（180°回すのと同じで、鏡写しにはならない）。
  号車と対面乗換帯は start と end を入れ替える
- 向きがデータの約束で1つに決まるので、`platformSide` は使われなくなる。列は廃止する（二段階で落とす）
- 図の描画から、ホームの側による分岐（`layoutRows()` の並び順の切り替えなど）を除く

`x = 0` の位置は従来どおり列車のデータから導出しない（停車位置パターンの増減で原点が動かない）。変わるのは「どちらの端か」の約束だけである。

## 却下した選択肢

### 描くときに `top` のホームだけ180°回す

データは変えず、`platformSide = top` のときだけ描画で回す。

- Admin の図も同じ見え方にするには、ドラッグで得た位置を「回したのを戻して」座標にする換算が要る
- ホームの側による分岐が、横の図にも #174 で作る縦の図にも残る。片方だけ反転し忘れる事故は、`layoutRows()` に side の解釈を集めて防いできた種類のもの
- 約束が「`x = 0` の端 × `platformSide`」の組のまま残り、新しいホームを入れる管理者が両方を正しく選ぶ必要がある

対象の座標が2ホーム分しかない今のうちに、データの側で約束を1つにするほうが安い。

### Web だけ回し、Admin は回さない

Admin に手を入れずに済むが、`top` のホームでは Admin の図と公開の図の向きが逆になる。
「編集中の図＝公開の図」（ADR-0010）が崩れる。

### 1号車の位置を基準に向きを決める（上や左を1号車にする）

号車番号の向きは列車ごとに違い、同じホームに逆の列車が来ると向きを決められない。
また、ホームによっては現実の鏡写しになる。

## 影響

- `top` だった2ホームの座標が書き換わる。Admin でも公開の図でも、この2ホームは180°回った見え方になる
- 新しいホームを入れる管理者は、線路に向かって左の端を `x = 0` にする。Admin のホームの編集欄にこの約束を示す
- 外部の資料（駅の構内図など）が逆向きに描かれていても、座標は約束の向きで入れる
- 原点の定義を変える作業なので、`docs/domain/platform-coordinate-system.md` を書き換える
- 図の上下が固定になるので、ADR-0006 と ADR-0010 にある `stripOrder`（side から帯の並び順を決める）に関する記述は失効する。両 ADR の決定の本体は変わらない

## 再評価の条件

- 線路に向かう向きが決まらないホーム（両側に線路がある1つの番線、など）を扱う必要が出たとき
