# ADR-0012: 設備0件のルートを「設備未入力」とし、必要な行為を導出しない

- **ステータス**: Proposed
- **日付**: 2026-09-26
- **決定者**: @Natsugure
- **関連**: [ADR-0011](./0011-transfer-route-facilities-as-set.md),
  [`docs/domain/station-master-model.md`](../domain/station-master-model.md)「乗換難易度」節,
  GitHub Issue #123 / #124 / #125

---

## コンテキストと課題

Issue #123 で旧 `station_connections` の評価済み行を新モデルへ移す際、旧データから設備の種類が
確認できないルートがあった。開発者判断で、こうしたルートも**設備0件**のまま移すことにした
（移さない案は、評価済みの接続を失うため却下）。

ところが、ペルソナごとの「必要な行為」の導出（[ADR-0011](./0011-transfer-route-facilities-as-set.md)）は
「ルート上の設備すべてから最も重いものを選ぶ」関数であり、**空集合に素直に適用すると
最も重いものが無く、「そのまま通れる」と読める**。

例えば淡路町↔新御茶ノ水の基準ルートは設備0件で移す。そのまま導出すると、旧データで
`inaccessible`（ベビーカーはバリアフリールートが無い）だった接続が「そのまま通れる」と表示される。
利用者に誤ってバリアフリーだと伝える方向の誤りであり、影響が大きい。

## 決定

`transfer_route_facilities` に行が無いルートは「設備が無い」ではなく**「設備未入力」**を表す。

- 段差の無いルートは、設備0件ではなく `sameFloor` を明示する。これにより「段差が無い」と「未入力」が区別できる。
- 表示層（#125）は、設備0件のルートについて必要な行為を導出せず、バリアフリールートにも数えず、
  「設備の情報が未入力」と示す。
- Admin（#124）の重複ルート検出（設備の種類の集合と4フラグの一致）は、設備0件のルートを対象外にする。
  未入力どうしは中身が分からないため「一致」とは言えず、対象に含めると無関係なルートを同一と判定して
  統合を提案してしまう。

「接続が無い＝未評価」と同型の、**行が無いことによる表現**である。

## 却下した選択肢

### 「未入力」を表す設備コード（`unknown` 等）を `facility_types` に足す

未入力を明示的な行で表す案。設備の種類のマスタに「設備ではないもの」が混ざり、
`unknown` と実在の設備が同じルートに同居する状態（一部だけ判明している等）の意味づけも要るようになる。
未入力は「行が無い」で十分に表せ、接続の未評価を「行が無い」で表すのと同じ形で揃う。

### 設備0件のルートを移さない

確認できないルートは移行対象から外す案。開発者が却下した。評価済みの接続（難易度・備考・フラグ）を
失い、旧モデルでは表示できていた情報が新モデルで消える。

## 影響

- **#124（Admin）と #125（Web 表示）が守る制約**になる。現時点では新モデルを読むコードが無いため害は無いが、
  #125 が空集合を「そのまま通れる」と読むと誤表示になる。
- 接続単位の4状態（未評価／バリアフリールートなし／単一／複数）とは別に、ルート単位の「設備未入力」が加わる。
  表示層はこの状態を区別して扱う必要がある。
- #123 は設備0件のルートを複数作るため、Admin での設備の追記が前提になる。

## レビュー

#125 の着手時に、表示層が本ADRの制約を実装したことを確認し、`Accepted` にする。
実装の過程で「未入力」を行で明示する必要が生じた場合（例: 一部の設備だけ判明しているルートを区別したい）は、
`unknown` コードの案を再検討する。
