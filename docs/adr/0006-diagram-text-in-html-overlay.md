# ADR-0006: ホーム図のテキストは SVG ではなく HTML オーバーレイ層に置く

- **ステータス**: Proposed
- **日付**: 2026-08-23
- **決定者**: @Natsugure
- **関連**: [ADR-0001](./0001-layer-structure.md), [`docs/domain/platform-coordinate-system.md`](../domain/platform-coordinate-system.md)

---

## コンテキストと課題

ホーム図は、コンコース単位で「どの階段・エレベーターがどの出口・どの乗り換えに通じるか」を
示す。その出口名と乗り換え先を、当初はすべて SVG の `<text>` として図の中に描いていた。

**この構成では情報の省略が構造的に避けられない。**

### 問題1: SVG の `<text>` は折り返せない

SVG に自動折り返しは無い。1要素は必ず1行になる。
収まらない文字列は、はみ出させるか、切るかの二択になる。

### 問題2: 描画前に文字の実幅が測れない

viewBox の単位はメートルなので、フォントサイズもメートルで指定することになる。
サーバーサイドレンダリングの時点で `<text>` の実幅は分からないため、
全角1em・半角0.5emという概算に頼るしかなかった。

```ts
// 旧 domain/concourseLayout.ts
export const MAX_LABEL_WIDTH_METERS = 44;   // 5px/m 換算で 220px
export function truncateToWidth(text, fontSize, maxWidth): string  // 末尾を「…」で切る
```

### 問題3: 結果として、実データで情報が落ちていた

乗り換え先の路線名は「接続先駅に乗り入れる**全**路線」である。
新宿・渋谷級では6路線以上になり、図に収まらない。そのため

- `connectionShortLabels()` が3路線以上を「◯◯線ほか5」に畳み、方面名も落としていた
- さらに `truncateToWidth()` が「…」で切っていた

全文の参照先は `<title>` のホバーと図の外のテキストリストだけになる。
**`<title>` のホバーはタッチ環境で開けない。** 主要な閲覧環境がモバイルである本アプリで、
これは事実上「読めない」に等しい。

省略を前提にした設計は `docs/domain/platform-coordinate-system.md` にも
明文化されていた（「図のラベルは短縮し、全文は `<title>` とテキストリストに残す」）。
つまりこれは実装の不備ではなく、**方針そのものを覆す必要がある**。

## 決定

**図のテキストを SVG の外へ出し、同じ x スケールを共有する HTML のオーバーレイ層に置く。**

SVG は幾何（ホーム帯・号車・乗車位置目標・設備アイコン・束ね線・対面乗り換えティント）
だけを担当する。出口名・乗り換え先・対面乗り換えの案内文は HTML が持つ。

層をまたぐ x の対応は、ピクセルではなく **`xFraction()` が返す割合（0..1）**で取る。
SVG は viewBox のメートル座標で、HTML は CSS のパーセントで同じ割合に落ちる。

これにより、折り返し・実測レイアウト・背景と枠線・テキスト選択・スクリーンリーダー対応が
すべてブラウザの標準機能として手に入る。**文字を切り詰める理由が無くなる。**

文字幅の推定（`estimateTextWidth()`）は残すが、用途を
**「どの段に置くか」の判断だけ**に限定する。推定を外しても、プレートが折り返して
少し位置がずれるだけで、情報は1文字も失われない。

## 却下した選択肢

### SVG `<foreignObject>` で HTML を SVG の中に入れる

SVG の中に HTML を置けるので、折り返しは手に入る。
**しかし中身の高さが SVG の高さに反映されない。** viewBox の高さは事前に決める必要があり、
「何行に折り返すか分からないものを収める」という根本問題が残る。
Safari での実装差も踏まえると、得られるものが少ない。

### Client Component にして `useLayoutEffect` で実測し、SVG を再レイアウトする

正確な幅が得られるので、SVG の中に置いたまま最適配置ができる。
**しかし Server Component 既定という方針を崩す。** 初回描画のちらつきと
ハイドレーション境界を、表示のためだけに持ち込むことになる。
実測はブラウザの CSS にやらせれば済む話であり、JavaScript で測る必要が無い。

### サーバー側で実フォントのメトリクスを測る（opentype.js 等）

概算をやめて正確に測る案。図の書体は `next/font/google` で BIZ UDPGothic に固定して
配信しているため、測ること自体は可能である。

**しかしそれでも、測った幅で切るか否かという問題は残る。** 正確に測れたところで、
1行に収まらない文字列をどうするかの答えは「折り返す」であり、
それはブラウザが既にやってくれる。サーバー側でフォントを読み込み、
グリフ送りとカーニングを再現し、折り返し位置を自前で決める仕組みを作っても、
得られるのは CSS が無料でやることの再実装でしかない。

加えて、書体に含まれない字（外字・記号）はフォールバックに落ちるため、
測定が常に正しいとは限らない。**払うコストに対して、防げる失敗が無い。**

### 切り詰めを維持し、タップで全文を展開する

省略表示自体は残す案。
Client Component 化が必要になるうえ、**「図から読み取れない」が既定の状態になる。**
図の目的は一目で位置関係を掴むことなので、既定で読めないのは目的に反する。

### `PX_PER_METER` を下げて全部を図に収める

5px/m は「一度に見える両数」と「文字の判読性」の折衷点として決めた実測値である。
これを下げると号車番号（2.2m ≒ 11px）が判読できなくなる。
文字を読めるようにするために文字を読めなくする、という自己矛盾になる。

## 影響

- `docs/domain/platform-coordinate-system.md` の「コンコースの表現」節を書き換えた。
  短縮と `<title>` 退避の記述は失効した
- `layoutRows()` からラベル段の概念（`CONCOURSE_SLOT_HEIGHT` / `concourseSlotTops`）が消え、
  SVG の高さはコンコースの件数に依存しなくなった（22、束ね線ありで 24 の固定）
- `layoutRows()` は新たに `stripOrder` を返す。SVG外のオーバーレイをホームのどちら側に
  積むかも `platformSide` 依存なので、side の解釈を `layoutRows()` に一本化する原則を維持する
- **新しい不変条件**: `<svg>` に明示的な `height` を指定してはならない。
  指定するとレターボックスが生じ、オーバーレイとの x 対応が無言でずれる
- テキストリストの役割が変わった。従来は「省略された全文の参照先」だったが、
  図が全文を持つようになったため、**座標を持たないコンコース**（束ね線を引けないもの）
  の受け皿に限定した

## レビュー

図に出す情報の量が現在の想定を大きく超えたとき（例: 1コンコースに10路線以上の接続、
コンコースが5件以上近接して段が積み上がる）に再評価する。
その場合も本決定を覆すのではなく、プレートの折りたたみや優先順位付けなど
**HTML の中で解ける手段**を先に検討する。
