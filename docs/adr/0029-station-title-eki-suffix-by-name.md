# ADR-0029: 駅ページのタイトルで「駅」を足すかを駅名の文字だけで決め、名前に「駅」を含むものと「ステーション」で終わるものには足さない

- **ステータス**: Accepted
- **日付**: 2026-11-18
- **決定者**: @Natsugure
- **関連**: Issue #8（駅ページのタイトルに駅名・路線名を出す）, PR #250,
  [ADR-0007](./0007-station-master-data-source.md)（駅名は駅データ.jp のシードを手で維持する）

---

## コンテキストと課題

駅ページのタイトルは `<駅名>駅 <路線名> | ふらっと乗換` にする（Issue #8）。
「渋谷駅 エレベーター」のように「駅」を付けた形での検索が多いため、駅名に「駅」を足す。
最初の実装では、駅名が「駅」で終わるときだけ足さないようにしていた。

この作りでは、路面電車の停留場などで不自然な表記になる。

### 実測（2026-11-18、Neon の main ブランチ）

| 名前の形 | 件数 | 例 | 最初の実装の出力 |
|---|---|---|---|
| 「駅前」で終わる | 23 | 王子駅前（都電）、熊本駅前、駅前（豊橋鉄道） | 王子駅前**駅** |
| 途中に「駅」がある | 5 | 旭駅前通、駅前大通、宇都宮駅東口、駅東公園前、電鉄富山駅・エスタ前 | 旭駅前通**駅** |
| 「ステーション」で終わる | 4 | 東京ディズニーランド・ステーション（舞浜リゾートライン） | 〜ステーション**駅** |
| 「駅」で終わる | 6 | 富山駅、広島駅（路面電車の停留場名）、湖遊館新駅 | 足さない（正しい） |
| 「駅」で始まる地名 | 1 | 駅家（JR西日本 福塩線。正式には駅家駅） | 駅家駅（正しい） |
| 空港・ターミナルで終わる | — | 関西空港、羽田空港第1ターミナル | 関西空港駅（正式名と同じで正しい） |

「バスセンター前」や「三ノ輪橋」のように、正式には「停留場」であるのに「駅」が付くものもある。

### 制約

- 停留場かどうかを表す列は DB に無い
- 駅名は手で維持する（ADR-0007）。新しい事業者を足すと、名前の形も増える

---

## 検討した選択肢

1. **駅名が「駅」で終わるときだけ足さない**（最初の実装）
2. **駅名が「駅」「駅前」で終わるときは足さない**
3. **駅名に「駅」を含むか、「ステーション」で終わるときは足さない** ← 採用
4. **3 に加えて、「駅家」のような例外の名前を一覧で持つ**
5. **停留場かどうかを DB に持ち、停留場には足さない**
6. **全駅で「駅」を足さない**

---

## 決定

`stationPageTitle`（`apps/web/src/features/station/domain/pageTitle.ts`）では、駅名が次のどちらかに当たるときは「駅」を足さない。

- 名前のどこかに「駅」を含む
- 「ステーション」で終わる

駅名の文字だけで決め、停留場かどうかは見分けない。
「駅家」のように「駅」で始まる地名にも「駅」は足さない。そのため正式名の「駅家駅」とはずれるが、これは受け入れる。

---

## 各選択肢の評価

### 1. 駅名が「駅」で終わるときだけ足さない

- **良い点**: 一番単純
- **悪い点**: 「王子駅前駅」「〜ステーション駅」のように、ユーザーに見える表記が32件で不自然になる
- **却下理由**: ブックマークや共有したリンクに、事実と違う名前が残る

### 2. 駅名が「駅」「駅前」で終わるときは足さない

- **良い点**: 都営・東京メトロの名前は、これで足りる
- **悪い点**: 「旭駅前通」「宇都宮駅東口」のように途中に「駅」がある名前と、「〜ステーション」は直らない
- **却下理由**: 末尾の形を1つずつ足していくと、事業者が増えるたびに取りこぼしが出る。
  名前に「駅」を含めば、どの形でも「駅」が二重になる

### 4. 3 に加えて、「駅家」のような例外の名前を一覧で持つ

- **良い点**: 「駅家駅」を正しく出せる
- **悪い点**: 今の該当は1件だけで、名前を変えたり事業者を足したりするたびに、一覧の見直しが要る。
  判定がルールと一覧の2か所に分かれ、読みにくくなる
- **却下理由**: 「駅家 福塩線」でも路線名が並ぶので、どの駅か分かる。1件のために一覧を持つ手間は見合わない

### 5. 停留場かどうかを DB に持ち、停留場には足さない

- **良い点**: 「三ノ輪橋駅」「バスセンター前駅」のように、正式には停留場であるものも正しく出せる
- **悪い点**: スキーマの変更と、全駅の区分を手で入れる作業が要る。
  鉄道事業法上の駅と軌道法上の停留場の区別は、利用者にとっての意味が薄い
- **却下理由**: タイトルの表記のためだけに、駅マスタの維持の手間を増やさない

### 6. 全駅で「駅」を足さない

- **良い点**: 例外が無く、表記がずれることも無い。路線名が並ぶので、地名の「渋谷」と取り違えられる心配も無い
- **悪い点**: 「渋谷駅 エレベーター」のように、「駅」を付けた形での検索が多い。
  検索結果では、検索語と一致した部分が太字になる。タイトルに「渋谷駅」とあれば、そのまま一致して目に留まりやすい
- **却下理由**: 多くの普通の駅で、検索結果に見えるタイトルの分かりやすさが落ちる。
  順位への影響は小さいと見ているが、不自然な表記が出るのは一部の駅だけである

---

## 結果

### 肯定的な結果

- 「駅前」「駅東口」「・ステーション」のような名前で、「駅」が二重になったり、不自然に付いたりしなくなる
- 判定は駅名の文字だけで済み、DB の変更が要らない
- 新しい事業者を足しても、名前に「駅」を含む形なら、ルールを変えずに正しく出る

### 否定的な結果・受け入れるトレードオフ

- 「駅家」のように「駅」で始まる地名は、正式名の「駅家駅」ではなく「駅家」と出る（2026-11-18 の時点で1件）
- 「三ノ輪橋」「バスセンター前」のように正式には停留場であるものにも、「駅」が付く

### 見直し条件

- 「駅」で始まる地名や、「ステーション」以外で終わる駅でない名前（「〜停留場」など）が増え、不自然な表記が目立つようになったとき
- 停留場かどうかを、別の目的で DB に持つことになったとき。そのときは選択肢5に切り替えるかを決める
- 検索の流入を Search Console で見て、「駅」を足すことに効果が無いと分かったとき（選択肢6）
