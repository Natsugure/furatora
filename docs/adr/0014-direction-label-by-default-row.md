# ADR-0014: 方面の表示文言を、(路線, 走行方向) ごとの既定行で解決する

- **ステータス**: Accepted
- **日付**: 2026-09-27
- **決定者**: @Natsugure
- **関連**: [`docs/domain/station-master-model.md`](../domain/station-master-model.md)「接続の端点」,
  GitHub Issue #130 / #125 / #128

---

## コンテキストと課題

乗換接続の端点は `(stationId, direction_type)` で、`direction_type` は `'inbound' | 'outbound'` の2値である（#30）。
`line_directions.id` を参照しないため、「池袋方面」のような**方面の表示文言**を端点から引く手段がない。

文言を持つのは `line_directions.displayName` だが、次の2つの理由で `(lineId, direction_type)` から文言が1つに決まらない。

- **同じ組に同じ意味の行が複数ある。** 駅ごとの掲示の違いをそのまま行にしているため
  （丸ノ内線 inbound は「東京・新宿・荻窪・方南町方面」「新宿・荻窪・方南町方面」「荻窪・方南町方面」など5行）。
  2026-09-27 時点で52行・28組のうち10組が複数行を持つ。
- **駅ごとの文言を引ける経路は `platforms`（ホーム）だけで、登録は20駅分しかない**（丸ノ内線と銀座線）。

#125 で Web に「淡路町の池袋方面は途中階段」のように表示するには、ホームが無い駅でも文言が決まる必要がある。

## 決定

1. `line_directions` に `is_default boolean NOT NULL DEFAULT false` を持たせ、部分ユニークインデックス
   `unique_line_direction_default (line_id, direction_type) WHERE is_default` で、**組ごとに既定行を高々1行**にする。0行も許容する。
2. 方面ラベルは次の順で解決する。
   ① その駅のその路線のホームが、その走行方向の枠に持つ文言 → ② 組の既定行の文言 → ③「上り」「下り」。
   ① は駅ごとの掲示で最も正確なので、ある限り優先する。② はホームが無い駅のための既定値である。
3. **既定にするのは、途中の駅名を含まない、終点方向の文言**（路線上の大半の駅で表示しても誤りにならない文言）とする。
   ② はホームが無い**すべての駅**で同じ文言として表示されるため、特定の区間でしか正しくない文言は既定に向かない。
   どの駅でも通用する文言が既存行に無い路線（環状部を持つ大江戸線）は、新しい行（「内回り」「外回り」）を作って既定にする。

## 却下した選択肢

### `lines` に既定の方面を指す FK を2列持たせる（`default_inbound_direction_id` / `default_outbound_direction_id`）

1路線につき高々1行を構造で保証できる。しかし、参照先の `direction_type` が列名と一致すること、参照先の `line_id` が
その路線であることを CHECK で書けない（別の表の値を見るため）。既定を「行の性質」ではなく「路線の性質」として持つと、
方面の行を消したときの扱い（FK の `ON DELETE`）も別に決める必要がある。部分ユニークなら、組と既定が同じ行にあり、ずれようがない。

### 同じ意味の行を統合して、組ごとに1行にする

解決規則が要らなくなる。しかし、ホームが参照している駅ごとの掲示の文言（① の情報源）が消える。
新宿駅のホームに「東京・新宿・荻窪・方南町方面」を出すのは誤りで、駅ごとの行は必要である。

### 読み取りのたびに、ホームからの参照件数が最多の行を選ぶ

Issue #130 の当初案（「駅ごとの掲示文言のうち最も一般的なもの」）に近い。次の理由で却下した。

- ホームが登録されていない路線（2026-09-27 時点で14路線中12路線）では、件数がすべて0で決まらない。
- ホームを登録するたびに、ほかの駅の表示が変わる。
- 件数が最多の文言は、途中の駅名を含むことが多い。丸ノ内線 inbound の最多は「東京・新宿・荻窪・方南町方面」（8件）で、
  既定にすると新宿駅や東京駅でも「東京・新宿…方面」と表示される。

### 代表駅（`representative_station_id`）から「○○方面」を組み立てる

データの追加が要らない。しかし、直通先（「東急線・相鉄線方面」など）の情報が落ちる。環状部を持つ路線では、
代表駅から意味のある文言を作れない。

## 影響

- 方面の表示文言は `resolveDirectionLabel`（`packages/transfer-difficulty`。DB・React に依存しない純粋関数）で解決する。
  Admin の駅対編集画面と、#125 の Web が同じ関数を使う。
- **既定行を持たない組は「上り」「下り」と表示される。** 路線や方面を追加したら、Admin の方面フォームで既定を設定する。
- 既定を別の行に移す書き込みは、旧既定を外す文と新既定を立てる文の2文になるので、`withTransaction`（ADR-0005）で行う。
- ① が複数件になる駅（中野坂上 inbound。1つの走行方向に複数のホームが対応する）は、どちらかに決めずに連結して表示する。
  解消は #128。

## レビュー

次のいずれかで再評価する。

- 駅ごとに文言を変えたいが、ホームを登録するほどではない、という要望が出たとき（駅単位の上書きを検討する）。
- 物理駅粒度への統合（#82）で、1駅が複数路線を持つようになったとき（解決の入力に路線を明示する必要がある）。
