# 要件: フリースペース・優先席のドア番号を、その号車のドア数の範囲内に限る (Issue #194)

## 概要

- **対象**: Admin の列車の作成・編集（`TrainForm`、`trainSchema`、`/api/trains`・`/api/trains/[trainId]`）
- **参照**: [design.md](./design.md) / [tasks.md](./tasks.md) / [Issue #194](https://github.com/Natsugure/furatora/issues/194)
- **進め方**: 1 つの PR（`fix/issue194-near-door-range`）
- **信頼度**: 90%（高）。範囲の判定は単純で、置き場（schema の `superRefine`）も stop-pattern に前例がある。不確かな点は、フォームで行ごとにエラーを出す形（いまは失敗すると `alert` だけ）

## 背景

フリースペース・優先席の `nearDoor`（ドア番号）が、その号車の `doorCount` の範囲内にあるかを確かめていない。範囲外の値を保存すると、
ホームの図はドアを号車の外に描き、図の下の一覧には「5番ドア付近」と出て、両者が食い違う。

本番 DB に範囲外の値は無い（2026-10-23 に Issue のコメントで確認済み）。残っているのは入力側の検証だけ。
表示側で範囲外のドアを消す案（Issue の対応案 4）はとらない。範囲外のデータが残ったときに、図の上で見えるほうがよいため（Issue のコメント）。

## 要件（EARS）

- **REQ-1**: フリースペース・優先席の `nearDoor` が `1..（その号車の doorCount）` の外にある列車を保存しようとしたとき、API は 400 を返し、保存しないこと
- **REQ-2**: フリースペース・優先席の `carNumber` が車両構成（`carStructure`）に無い号車のとき、API は 400 を返し、保存しないこと
- **REQ-3**: REQ-1・2 のとき、API のエラーの issue の `path` は、該当の設備の行（`['freeSpaces', i, 'nearDoor']` など）を指すこと
- **REQ-4**: フォームで、範囲外のドア番号または車両構成に無い号車が入っている間、システムはその行の入力の下にエラーの文を出すこと
- **REQ-5**: REQ-4 の行があるまま「登録」「更新」を押したとき、システムは送信せず、入力に誤りがあることを通知すること
- **REQ-6**: フォームのドア番号の入力は、矢印キー・増減ボタンでは、その行の号車の `doorCount` を超えないこと
- **REQ-7**: 範囲外のドア番号を入力したとき、システムは値を上限に丸めず、入力したままにすること（丸めると、入力していない別のドアが黙って保存される。dev サーバーでの確認で見つけた）

## エッジケース

| 入力 | 期待 |
|---|---|
| 4 ドアの号車に `nearDoor=4` | 通る |
| 4 ドアの号車に `nearDoor=5`・`nearDoor=0` | 拒否（`nearDoor` の行） |
| 両数を減らし、設備の号車が無くなった | 拒否（`carNumber` の行） |
| 号車のドア数を減らし、設備のドア番号が範囲外になった | その行にエラーが出る |
| ドア番号に 9 を入れて（3 ドア）「更新」を押す | 9 のまま、その行にエラー、送信しない |
| `carStructure` が null で設備がある | 拒否（号車が無い扱い。フォームは常に `carStructure` を送るので、通常は起きない） |
| 設備が無い | 通る |
