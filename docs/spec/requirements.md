## 背景

1. 描画範囲の端にあるアクセス点で、設備アイコンが途切れる。`computeBounds()` がアクセス点の
   座標しか範囲に入れておらず、扇状に張り出すアイコンぶんが余白(5m)を超える。
2. 複数のコンコースが密集してレーンが分かれると、深いレーンへ降りるガイド線が
   出口・乗換プレートの上を通る。支柱の `transform` が stacking context を作り、
   `transform` を持たない端寄せプレートより前面に描かれる。

## 要件（EARS）

### R1 設備アイコンの欠け

- R1.1 アクセス点に設備アイコンを描くとき、システムは、すべてのアイコンが描画範囲（viewBox）に
  収まるよう描画範囲を算出すること
- R1.2 1つのアクセス点に設備が複数あるとき、システムは、扇状に並んだ両端のアイコンの
  外縁まで描画範囲に含めること
- R1.3 `xPositionMeters` が null のアクセス点の場合、システムは、描画範囲の算出に含めないこと
  （SVGには描かないため）
- R1.4 `computeBounds()` と `DiagramSvg` は、アイコンの寸法と間隔を同じ定数から得ること

### R2 ガイド線の重なり

- R2.1 深いレーンのプレートへ降りる引き出し線が手前のレーンのプレートと横位置で重なるとき、
  システムは、線をそのプレートの脇（隣り合うプレートの隙間）へ迂回させること
- R2.2 迂回先が描画範囲 [0, 1] を外れる場合、システムは、範囲内に残る反対側へ回すこと
- R2.3 迂回の横移動は、システムは、各レーンの図に近い側の余白帯の中だけで行うこと
- R2.4 両側とも迂回できない場合、システムは、線の位置を動かさず、線をプレートの背面に
  描くこと（プレートの文字を覆わない）
- R2.5 迂回した線は、システムは、最終的にプレートの中心（`anchorX`）へ戻ること
- R2.6 `platformSide` が `top` / `bottom` のいずれでも、システムは、R2.1〜R2.5 を満たすこと
- R2.7 迂回が不要な配置では、システムは、従来と同じ見た目（直進する縦線のみ）を保つこと

## 受け入れ基準

- 設備2件・3件のアクセス点を描画範囲の端に置いても、アイコンが欠けない
- レーンが2段以上のとき、線がプレートと交差しない（迂回不能時は背面）
- 既存テストが無変更で通る
