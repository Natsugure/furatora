## 概要

- **対象**: 新モデルのスキーマ（4テーブル）・設備コード追加・端点の正規化関数。
  読み書きするアプリコード（Repository・Admin UI・Web表示）は対象外
- **参照**: [design.md](./design.md) / [tasks.md](./tasks.md) /
  [Issue #122](https://github.com/Natsugure/furatora/issues/122) /
  ドメイン定義は Issue #30（commit 3c2fa0c 時点の `docs/spec/`。git 履歴に残る）
- **ブランチ**: `feat/issue122-transfer-difficulty-schema`

  出力するか（生成SQLで確認する）

## 背景

Issue #30 で、乗換難易度を「接続 → 接続とルートの紐付け → ルート → 設備」の4層で持つ
モデルを確定した。本Issueはそのスキーマを実装する。後続は
#123（評価済み16行の移行）→ #124（Admin入力）→ #125（Web表示）。

現行の `station_connections` は有向2行・方面なしで、Admin と Web が接続一覧と
難易度の両方を読んでいる。新モデルは無向1行・方面必須で行の意味が異なるため、
既存テーブルは改修せず、**新テーブルを追加する**（design.md 決定1）。

## 用語

- **接続**: 2つの端点 `(stationId, direction_type)` の組。無向。
- **乗換単位（ホーム）**: 物理ホーム。`direction_type` は乗換単位を一意に決めない。
  `stationGroups`（#96）の「乗換単位」は物理駅を指す別の概念であり、混同しないこと。
- **ルート**: 1本の物理経路。複数の接続から共有されうる。
- **接続とルートの紐付け**: `label`・`isBaseline` を持つ、接続×ルートの組。
- **基準ルート**: 一般利用者が案内される経路（迂回度の分母）。

## 要件（EARS記法）

### 接続

- **REQ-1**: システムは接続を、端点 `(stationId, direction_type)` × 2 の無向1行として
  保持できること。`direction_type` は `'inbound' | 'outbound'` で、両端点とも必須
  （`NULL` を許容しない）。
- **REQ-2**: 同じ端点対の接続を2行作ろうとした場合、システムはDB制約でこれを拒否すること
  （`NULLS NOT DISTINCT` を用いない）。
- **REQ-3**: 端点が正規化順（`(stationId, direction_type)` の昇順で A ≤ B）でない行を
  挿入しようとした場合、システムはDB制約でこれを拒否すること。両端点が完全に等しい行も拒否すること。
  `stationId` の同一性だけで端点を弾いてはならない（#82 で同一駅・方面違いが正当になるため）。
- **REQ-4**: 端点の正規化関数は、比較キーに `direction_type` を含め、`stationId` の
  大文字小文字に依らず DB の CHECK と同じ順序を返すこと。
- **REQ-5**: システムは接続の `notes` と `source`（`ekidata_group` / `manual` / `NULL`。
  現行を踏襲）を保持できること。

### ルート

- **REQ-6**: システムはルートを、接続に従属しない行として保持できること
  （`connectionId` を持たない）。所要時分 `minutes`（nullable）、4つの独立した真偽値
  （`isOutdoor` / `requiresExitGate` / `requiresStaff` / `isOfficiallyGuided`。既定 false）、
  `notes` を持つこと。
- **REQ-7**: システムは接続とルートを多対多で結び付け、紐付けごとに `label`（必須）と
  `isBaseline`（既定 false）を保持できること。ルートは複数の接続から共有できること。
- **REQ-8**: 同一接続内で `label` が重複する紐付け、または同じルートを同じ接続に
  2回結ぶ紐付けを作ろうとした場合、システムはDB制約でこれを拒否すること。
- **REQ-9**: 1つの接続に2本目の基準ルートを結ぼうとした場合、システムは部分ユニーク
  インデックスでこれを拒否すること。基準ルートが0本の接続は許容すること。

### 設備

- **REQ-10**: システムはルートごとに、直列に通る設備を `seq` 順で保持できること。
  `(routeId, seq)` の重複は拒否すること。
- **REQ-11**: 設備の種別は `facility_types.code` を参照し、既存6値
  （`elevator` / `escalator` / `stairs` / `ramp` / `stairLift` / `sameFloor`）に加えて
  `wheelchairEscalator` を持つこと。
- **REQ-12**: `seq` は直列の並びのみを表し、同じ段差に対する代替手段（階段と階段昇降機）は
  別ルートとして保持する、という帰属規則をスキーマのコメントに残すこと。

### 保持しないもの・移行

- **REQ-13**: システムはペルソナ別の列（可否・所要時分・フラグ・備考）を持たないこと
  （設備から表示層で導出する。#125）。
- **REQ-14**: 本変更は追加のみとし、既存テーブル・列を変更・削除しないこと。
  `station_connections` の難易度4列の削除は、それを読むコード（#125）が無くなった
  あとの別デプロイで行う（CLAUDE.md 禁止事項の二段階ルール）。
- **REQ-15**: `pnpm run build` は DB に書き込まないこと。新テーブルへのデータ投入は本Issueで行わない。
