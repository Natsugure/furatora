# 要件: ホーム図の編集で、編成の先頭・末尾を動かすと編成全体を平行移動する (Issue #201)

## 概要

- **対象**: Admin の駅レイアウト画面（ホーム図の編集）の、停車位置パターンの編集
- **参照**: [design.md](./design.md) / [tasks.md](./tasks.md) / [Issue #201](https://github.com/Natsugure/furatora/issues/201) /
  [docs/domain/train-stop-patterns.md](../domain/train-stop-patterns.md)「隣接号車は境界を共有する」 / [docs/domain/platform-coordinate-system.md](../domain/platform-coordinate-system.md)（図上編集）
- **進め方**: 1 つの PR（`fix/issue201-consist-shift`）
- **信頼度**: 90%（高）。変えるのは純関数 1 つとスナップの候補だけで、ハンドルの配置・向きの判定（`freeEdgeSides`）は今のまま使う

## 背景

列車の行の「1号車の先頭」「最終号車の末尾」のハンドルを動かすと、端の号車だけが伸び縮みする（`editDraft.ts` の `moveCarEdge`）。
停車位置を合わせる作業で動かしたいのは編成の位置で、号車の長さではない。号車の長さは車両構成から決まり、変えたいときは境界のハンドルで変えられる。

開発者と決めたこと（2026-10-25）:
- 先頭・末尾のどちらのハンドルも、編成全体を平行移動させる
- インスペクタの「先頭」「末尾」の数値入力も同じ動きにする（図のドラッグと数値入力は同じ純関数を呼ぶ決まり。platform-coordinate-system.md）
- 結果として、端の号車の長さだけを変える操作は無くなる

## 要件（EARS）

- **REQ-1**: 編成の外端（先頭・末尾）のハンドルを x へ動かしたとき、システムはその外端が x に来るよう、全号車の `startMeters`・`endMeters` に同じ差分を足すこと
- **REQ-2**: REQ-1 のあと、各号車の長さ（`endMeters - startMeters`）と、隣接号車の境界の共有は保たれること（反転編成でも）
- **REQ-3**: インスペクタの「先頭」「末尾」の数値入力を変えたとき、システムは REQ-1 と同じく編成全体を動かすこと
- **REQ-4**: 外端のハンドルをドラッグしている間、システムは動かしている編成自身の境界・ドアの位置にスナップしないこと（ホーム端・グリッドにはスナップする）
- **REQ-5**: 内側の境界のハンドルは、いまのまま境界だけを動かすこと
- **REQ-6**: 平行移動の結果は小数 2 桁に丸め、浮動小数の誤差で境界の共有が崩れないこと

## エッジケース

| 入力 | 期待 |
|---|---|
| 非反転 3 両（0-20-40-60）で 1号車の先頭を -5 へ | -5/15/35/55 |
| 非反転 3 両で 3号車の末尾を 65 へ | 5/25/45/65 |
| 反転 3 両（1号車 40-60 … 3号車 0-20）で 1号車の先頭（end）を 65 へ | 全号車 +5 |
| 外端でない edge（2号車の start など） | 無変更 |
| 差分が 0.1 のような小数 | 誤差の無い値（例: 20.1、40.1） |
