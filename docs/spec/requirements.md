# 要件: ホーム図を現実の見え方に合わせ、番線のカードに収める (Issue #174)

## 概要

- **対象**: Web の駅ページのホーム（番線のカード・ホーム図・フリースペースと優先席の一覧・乗換カード）、Admin のホーム図の見た目

- **進め方**: 5つの PR で `main` へ入れる（PR3 は着手時に 3a・3b に分けた）。この文書はすべての要件を持ち、design.md・tasks.md は着手した PR の節を詳しくする

- **信頼度**
  - PR1: 88%（高）。図の中身には手を入れず、番線のカードの器を変えるだけ。不確かな点は、スマホで閉じた番線が並んだときの見え方（目で確かめる）
  - PR3a: 86%（高）。見本と、着手時に開発者と決めた違い（design.md）に沿って、今の図の部品を描き替える。図の高さの約束（`layoutRows()`）は変えないので、Admin の編集レイヤに響かない

  - PR4: 着手時に見積もる

## 背景

ADR-0017 の見本は、すべての端末でホーム図を縦に描き、番線ごとの別ページに出す形だった。見本は見た目で決めたもので、UX として確かめていない。
#174 の検討で、現実の見え方を基準に、画面の幅で横と縦を切り替えることにした（ADR-0023）。その前提として、原点を「線路に向かって立ったときの左の端」に揃えた（#188・ADR-0022）。

今の駅ページは、番線ごとのカードに図をいつも開いた状態で並べている。スマホでは縦に長くなり、目当ての番線を探しにくい。

## 要件（EARS記法）

### 向き（PR3b で実装。PR1 で ADR-0023 に決める）

- **REQ-1**: システムはホーム図を回してよいが、鏡写しにしないこと。1号車を上・左に揃えないこと（ADR-0023）
- **REQ-2**: 画面の幅が `lg`（1024px）以上の間、システムはホーム図を横に描くこと。線路に向かって立った見え方（列車が上、ホーム・設備・プレートが下、左右は実際どおり）
- **REQ-3**: 画面の幅が `lg` 未満の間、システムはホーム図を縦に描くこと。横の図を左へ90°回したもの（列車は左、設備・プレートは右）。「上が1号車」の添え書きは出さない

### 出し方（PR1）

- **REQ-4**: システムは番線ごとの表示を別ページにせず、駅ページの番線のカードに収めること（ADR-0023）
- **REQ-5**: 画面の幅が `lg` 未満の間、システムは番線のカードを折りたためるようにし、既定では閉じておくこと
- **REQ-6**: 番線のカードが開いている間、システムはカードの頭と下の端の両方に「閉じる」操作を置くこと
- **REQ-7**: 下の端の「閉じる」でカードを閉じたとき、システムはカードの頭の開け閉めボタンにフォーカスを移すこと（長い図の下で閉じても位置を見失わないように）
- **REQ-8**: 画面の幅が `lg` 以上の間、システムは番線のカードをいつも開いた状態で出し、開け閉めの操作を出さないこと（見た目にも、支援技術にも）
- **REQ-9**: システムは番線のカードの頭に、番線・路線・編成・方面だけを出すこと。タグは出さない
- **REQ-10**: 番線に停まる列車の両数が複数ある場合、システムは編成を両数の小さい順に「8・10両編成」のように出すこと。列車が無い番線では編成を出さないこと
- **REQ-11**: 図を描けない番線（ホーム長が未登録、または列車が無い）の場合、システムは閉じた状態のカードの頭でそのことを示すこと
- **REQ-12**: 図を描けない番線で、カードの中に出すもの（位置未登録の設備・乗換、ホームの注記）も無い場合、システムは開け閉めの操作を出さないこと
- **REQ-13**: システムは方面タブと、ホームの前の案内文（「エレベーターの位置を参考に…」）を今のまま残すこと

### 一覧（PR2）

- **REQ-14**: システムはフリースペース・優先席の一覧を、すべての編成にあるものと一部の編成にだけあるものに分け、「全編成」「一部編成」の見出しを付けて出すこと

### 図の中身（PR3a。REQ-17 は PR3b）

- **REQ-15**: システムは横の図にも見本の新しい見た目（号車の札・ドアの縦棒・ローズの丸・角の丸め）を当てること。Admin の図は横のまま、見た目だけ変わること
- **REQ-16**: システムは対面乗換を、プレートと同じ列に、範囲を示す札として並べること
- **REQ-17**: 縦の図で、システムはプレートを CSS の流れで積み、プレートが本来の位置より押し下げられた場合は折れ線でその位置と結ぶこと。プレートの大きさを実測しないこと（ADR-0006 の範囲内）
- **REQ-18**: システムは出口のプレートを ADR-0018 決定3 に合わせること

### 乗換カード（PR4）

- **REQ-19**: 乗換のルートが複数ある場合、システムは最短のルートを大きく出し、ほかのルートは区切りの下に小さく並べること

| REQ-13 | 方面タブのある駅を dev サーバーで目で確かめる |

| REQ-16 | `PlatformDisplay` の描画テスト（対面乗換の札が図より後に出る）と、dev サーバーで目で確かめる |

## 範囲外

- タグと補足の文言の見直し（#189）
- 見本にある番線のカードのタグ（「出口 2か所」など）。REQ-9 により出さない
- 優先席の扱い（#175）

## 依存関係とリスク

| 依存・リスク | 影響 | 緩和 |
|---|---|---|
| 原点の約束（ADR-0022） | 縦の図は横の図を回すだけで描ける前提 | #188 で済んだ |
| PR1 だけが `main` に入っている期間 | 図の見た目は古いまま、器だけ新しくなる | 1つずつ公開してよい内容に分けてある（どの PR も単独で今より悪くならない） |
| `lg` の切り替えを CSS だけで行う（PR1） | 単体テスト（jsdom）では CSS が効かず、PC で開いていることを確かめられない | dev サーバーで目で確かめる |
| PR3b の縦のプレートの積み方 | 実測しないと押し下げを決められない可能性 | 着手時に PoC。だめなら ADR-0006 の範囲を見直す判断を記録する |

## エッジケース（PR1）

| ケース | 期待 |
|---|---|
| 列車が1つ | 「10両編成」 |
| 両数の違う列車が来る | 「8・10両編成」 |
| 両数の同じ列車が複数 | 「10両編成」（重ねない） |
| 列車が無い | 編成を出さない。頭に図を描けないことを示す |
| ホーム長0・列車あり | 編成を出す。頭に図を描けないことを示す |
| 図を描けない・位置未登録の設備も注記も無い | 開け閉めの操作を出さない |
| 図を描けない・注記がある | 開け閉めでき、開くと注記が出る |
| 方面タブを切り替える | 崩れない（開閉の状態は保たなくてよい） |
| PC で開け閉めボタンが見えない | 支援技術にも開け閉めの操作として伝えない（頭はボタンでなくなる） |
