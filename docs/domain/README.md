# ドメインドキュメント

このディレクトリは、**furatora が現在どういうシステムであるか**を記述します。

## 他のドキュメントとの使い分け

| 種類 | 問い | 置き場 | 更新方法 |
|---|---|---|---|
| 決定と却下理由 | **なぜ**その設計を選んだか | [`docs/adr/`](../adr/README.md) | 追記（覆すときは新ADRを作り `Superseded by` を付ける） |
| **現在のシステムの姿** | **いま**どうなっているか | **`docs/domain/`（本ディレクトリ）** | **上書き** |
| 特定Issueの作業計画 | この作業で**何をするか** | [`docs/spec/`](../spec/) | 使い捨て（次のIssueで全面書き換え） |

`docs/spec/` の3点セット（`requirements.md` / `design.md` / `tasks.md`）は
Issue ごとに全面的に書き換えられます。そこで確定したドメイン知識のうち、
**次のIssue以降も有効であり続けるもの**を本ディレクトリへ移します。

ADR との違いは「不変か、最新か」です。ADR は決定した時点の記録なので書き換えません。
本ディレクトリの文書は常に現在を指すので、古くなったら書き換えます。

## 運用ルール

> **追記しない。上書きする。**

- スキーマ・ドメインルールを変更するPRは、**同じPRで該当ファイルを直す**
- 「かつてこうだった」は書かない。それが必要なら git 履歴か ADR を見る
- 検討過程・却下案・その根拠は書かない。それは ADR の役割

## 状態表記

各文書の冒頭に**適用状況**を記載します。実装が追いついていない期間は、
どこまでが現実でどこからが予定かを明示します。
